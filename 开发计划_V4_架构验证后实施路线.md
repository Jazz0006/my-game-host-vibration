## 3. 已确认的平台边界

继续保持以下依赖方向：

```text
core
  → generic contracts only

domain
  → generic / legacy pure game state and mutations

games/werewolf
  → concrete Werewolf rules and projections

protocol/client
  → versioned multi-client contract + game-command mapping

runtime/shared
  → transport-neutral game/runtime composition

runtime/node
  → Express / Socket.IO / Node capability adapter

runtime/cloudflare
  → Worker / Durable Object / WebSocket capability adapter
```

硬约束：

- `core` 不 import Express、Socket.IO、Cloudflare runtime types 或具体游戏；
- `games/werewolf` 不 import runtime，也不反向 import client protocol；
- `protocol/client/ClientProtocol` 不依赖 Node、Socket.IO 或 Cloudflare runtime；
- `runtime/shared` 不 import Node 或 Cloudflare adapter；
- `runtime/cloudflare` 不反向 import `runtime/node`；
- Node / Cloudflare client protocol adapters 不互相依赖；
- socketId 永远不是稳定身份；
- `commandId` 是 transport/runtime concern；
- `actionId` 是 game interaction concurrency concern；
- Host 是 Recovery Controller，不是真人法官；
- PlayerView 私密信息边界不能为了开发便利被削弱；
- 不为了 BotC 提前建设大型规则 DSL。

上述边界已有自动 architecture tests 保护。

## 4. C 阶段恢复合同 ✅

核心恢复合同：

```text
stable playerId
+ resume token
+ authoritative RoomSnapshot
+ revision
+ bounded command receipts
+ explicit commandId
```

正常掉线、切 App、熄屏、Wi-Fi 短断、刷新等优先走 C1 resume；长期凭证丢失才进入 C4.3 Host-assisted identity recovery。

Host 可以重新提醒当前行动玩家、查看 privacy-safe 聚合 recovery status，并为离线的其他玩家生成短期一次性 recovery code，但不能默认查看身份、秘密行动目标或替玩家提交秘密操作。

夜间秘密 interaction 已有 timeout、接近超时提醒、单次延长、safe recovery、reconnect 后 timeout state 恢复和 deadline race 测试。Host 也可在异常情况下以 commandId 幂等方式 abort 当前游戏并返回 lobby。

## 5. D 阶段 Cloudflare 迁移 ✅

### D1 — Cloud Room abstraction

D1.1 建立 transport-neutral `RoomCommandRuntime`：

```text
transport authorization
      ↓
stable actor scope + commandId
      ↓
RoomCommandRuntime
      ↓
GameModule mutation
```

D1.2 将 Node 房间 delivery 收敛到单一 canonical projection，避免 timed wrapper 维护第二套 room view。

### D2.1 — Worker + Durable Object Skeleton

```text
roomCode → Durable Object name
one room = one authoritative DO
Worker room routing
Wrangler Durable Object binding
```

### D3 — Durable Object Snapshot Persistence

Durable Object Storage 持久化 platform-neutral `RoomSnapshot`，不持久化 socketId、connected 或 plaintext resume token；恢复 membership、game state/config、ruleState、pendingInteraction、revision 和 bounded command receipts。

### D4 — Hibernation WebSocket

PR #31 已完成并通过 CI：

- Durable Object Hibernation WebSocket；
- `user:<playerId>` stable tag；
- serialized attachment 保存连接身份；
- DO eviction / reconstruction 不依赖内存 session map；
- 同一 stable player 新连接替换旧连接；
- player unicast / room broadcast；
- 长期 resume token 先换短期一次性 WebSocket ticket；
- ping/pong 使用 auto-response。

### D5 — Node / Cloudflare Parity

PR #32 已完成并通过 `typecheck + npm test`。

Werewolf room command executor 已抽到 `runtime/shared`；Node 和 Cloudflare 只提供各自 crypto / clock / storage / transport capability。Cloudflare 从 D3 snapshot 恢复房间，通过同一个 `RoomCommandRuntime` 执行 commandId dedupe，非 replay mutation 只递增一次 revision，并重新保存 pending interaction 和 command receipts。

核心验收：

```text
same authoritative snapshot
+ same command / actor / commandId
+ equivalent runtime dependencies
→ same authoritative game result
```

## 6. E1 — Client Protocol Boundary ✅

PR #34 已完成，并通过 `npm run typecheck` 与完整 `npm test`。

### 6.1 稳定协议四族

客户端与服务器的长期合同收敛为：

```text
Command Envelope
State / Player View
Realtime Event
Reconnect
```

所有协议消息带显式 protocol version。游戏命令基本形状为：

```text
protocolVersion
kind = command
commandId
command type
payload
```

需要 interaction concurrency 的命令继续在 payload / game command 中携带 `actionId`；`commandId` 与 `actionId` 不合并。

### 6.2 Reconnect 合同

Reconnect 继续使用：

```text
roomId
playerId
resumeToken
```

恢复后以 authoritative state / player view 为唯一真相，不做 realtime event replay。

### 6.3 Legacy Socket.IO surface 已完整审计

现有 Web / Node Socket.IO 的 client→server handlers 与 server→client deliveries 已全部纳入 `LegacySocketIoSurface` 清单，并自动测试当前 `server.ts` / `timedServer.ts`，防止以后新增事件绕开协议分类。

现有事件均必须归入四类协议之一，而不是形成新的第五套 transport API。

### 6.4 Werewolf protocol command mapping

第一轮 executable mapping 覆盖现有 post-start Werewolf commands，包括确认身份、狼/女巫/预言家/守卫/猎人行动、投票以及 Host 的开始夜晚、关闭投票、进入下一夜等。

协议层映射到既有 `WerewolfCommand`，规则模块本身不 import client protocol。

### 6.5 Node / Cloudflare protocol adapter

两端均可接受同一 transport-neutral protocol command：

```text
same protocol command
        ↓
Node adapter / Cloudflare adapter
        ↓
existing authoritative command runtime
        ↓
same shared Werewolf mutation path
```

Host authority 在 adapter boundary 检查。

### 6.6 Private player view contract

private Werewolf player projection 已从 Node adapter 抽到 `runtime/shared/werewolfRoomView`。

因此：

```text
same stable playerId
+ same authoritative room state
→ equivalent private player state envelope
```

Node 与 Cloudflare parity test 已覆盖该合同。

### 6.7 E1 明确没有做

E1 没有改写现有 Web UI，也没有把 `public/app.js` 全量切换到新协议；没有实现微信小程序 UI、账号体系、event sourcing、支付、排行榜或 BotC production rules。

这些限制是有意保持 PR 边界，现有可玩 Web 版本不因 E1 被重写。

## 8. E2 — Web Client Adapter Migration ← 下一步

### 8.1 目标

将当前 `public/app.js` 对一对 Socket.IO event name 的直接依赖，逐步迁移到 E1 建立的 client protocol，而**不重写 UI 和游戏体验**。

E2 的核心不是换前端框架，而是增加清晰的 Web transport/client adapter，使页面逻辑只处理：

- protocol command；
- state / player view；
- realtime event；
- reconnect lifecycle；
- browser capability（vibration / audio / visibility）。

### 8.2 第一 PR 建议范围

先迁移 post-start Werewolf game commands，而不是一次搬完建房、恢复、房间管理和测试工具：

1. 建立 Web client protocol adapter；
2. 将现有 `emitCommandWithAck()` 的狼人杀游戏命令映射到 E1 protocol command envelope；
3. Node Socket.IO 继续作为 transport，但通过 protocol adapter dispatch；
4. 保持同一 user action retry 复用同一 `commandId`；
5. 保持 `actionId` 原有并发语义；
6. state / private player view 保持与现有 UI 兼容；
7. 增加 Web adapter mapping / integration tests；
8. 不改变页面视觉和实际游戏流程。

这一小步验证稳定后，再迁移 room-management、reconnect/recovery、timeout 与 realtime events。

### 8.3 E2 明确不做

第一 PR 不同时做：

- Web UI 大改版；
- 移除 Socket.IO；
- 微信小程序；
- Cloudflare production cutover；
- BotC production rules。

Socket.IO 在 E2 仍可作为 Node transport；目标是让业务页面不再把 Socket.IO event name 当作长期业务协议。

## 9. 多客户端 / 微信小程序原则

震动、音频、生命周期属于 capability adapter：

```text
Web              → navigator.vibrate / browser lifecycle
WeChat Mini App  → wx vibration / mini-program lifecycle
Future native    → native haptics / native lifecycle
```

客户端只负责：

- 显示 server-provided view；
- 收集用户输入；
- 生成 commandId；
- retry 同一 user action 时复用 commandId；
- reconnect；
- vibration / audio 等本地 capability。

客户端不负责：

- 判定狼人杀规则；
- 推进 authoritative phase；
- 自行计算秘密结果；
- 复制 GameModule 逻辑。

每个 PR 保持小范围：

1. 一个主要架构目标；
