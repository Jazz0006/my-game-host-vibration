# 3. 当前必须保持的核心不变量

## 3.1 连接状态

> **Socket connected 不等于 game session synchronized。**

ClientSession 只有在 authoritative PlayerView 已接受后才能进入 `Connected`。

标准路径：

```text
Connecting / Reconnecting
        ↓ transport open
Syncing
        ↓ authoritative PlayerView accepted
Connected
```

## 3.2 Reconnect

Reconnect 的 source of truth 是 authoritative state：

```text
reconnect
   ↓
identity restored
   ↓
authoritative PlayerView sync
   ↓
revision reconciliation
```

不是：

```text
reconnect -> replay full realtime history
```

## 3.3 Revision / generation

- newer revision：apply；
- equal revision：duplicate，合法；
- lower revision：stale；
- stale generation：ignore；
- reconnect 可以推进 generation，但保留最后可信 PlayerView，直到新 generation 同步完成。

## 3.4 Realtime effect

Effect 不是 authoritative state：

- vibration / audio 可以丢失；
- 可以重复；
- 可以乱序；
- malformed transient effect 必须 nonfatal；
- unsupported browser capability 必须安全 no-op；
- reconnect 不要求 replay 所有 effect。

Effect Outbox 仍属于 R1，不提前塞进 E2.3。

## 7.3 E2.3c1 — Canonical private PlayerView delivery ✅ — PR #52

### 审计结论

`room:state` 与 `player:game-state` 不能一起删除。

生产 Web 仍然使用 `room:state` 提供：

- lobby 玩家列表；
- 在线 / 离线状态；
- Host 身份与管理权限；
- seat management；
- role configuration；
- Host game progress；
- vote tally；
- test prompt host status；
- exit / host transfer 等 room-management UI 所需数据。

因此：

> **`room:state` 当前必须保留。不要把它当作 private PlayerView 的重复路径删除。**

另一方面，生产 Web 已经没有 `player:game-state` listener；private PlayerView 由 ClientSession 接受 `client:state` 后渲染。

### E2.3c1 修改前

```text
broadcastRoom
   ↓
player:game-state       ← legacy canonical source
   ↓ onAnyOutgoing shadow
client:state            ← stable state 反而依赖 legacy emit
```

这是错误的迁移依赖方向。

### E2.3c1 修改后

```text
broadcastRoom()
   ├─ room:state                         ← public / Host UI，继续保留
   │
   └─ SocketIoClientStateDelivery
          ├─ client:state                ← canonical private PlayerView
          └─ player:game-state           ← compatibility only
```

新增：

```text
src/runtime/node/SocketIoClientStateDelivery.ts
```

并删除：

```text
SocketIoClientProtocolTransport
  onAnyOutgoing("player:game-state") shadow bridge
```

Revision 语义保持：

- 每次 private state push advance 一次 revision；
- `client:sync-state` 只读取当前 revision，不自行 advance；
- reconnect 后新的 push 可以产生更高 revision；
- PlayerView projection 本身不变。

# 13. R1 — Reliability Hardening / Effect Outbox

这一阶段放在 Client Runtime 与主要 transport boundary 稳定后、正式 production cutover 前。

目标解决：

```text
state commit success
but post-commit external effect delivery interrupted
```

候选：

```text
command receipt
+ authoritative state
+ durable effect record
```

形成同一 commit boundary，再由 DO alarm / retry worker 执行需要 eventual delivery 的 effect。

第一阶段不要把所有震动 / 动画 durable 化。

普通 transient vibration/audio 仍应保持 best-effort，除非有明确产品需求证明其必须 eventual delivery。

---

# 14. Durable User Event 的采用原则

仅当满足：

```text
must eventually reach one user
AND cannot be reconstructed from PlayerView
AND has stable eventId
AND supports ACK
```

才加入 durable user inbox。

普通 room recovery 仍坚持：

```text
reconnect -> authoritative state
```

而不是：

```text
reconnect -> replay full event history
```

# 22. 开发纪律

继续采用：

```text
inspect design + current code
→ choose smallest boundary change
→ contract / regression tests
→ production integration
→ typecheck
→ full test
→ CI
→ final diff audit
→ squash merge
```

原则：

- 不因为某 legacy event “看起来旧”就删除；
- 先证明 stable replacement 是 canonical source；
- production Web 不应同时消费新旧两条等价 effect/state 路径；
- room/public state 与 private PlayerView 分开判断；
- recovery correctness 优先于 transport cleanup 的整齐程度；
- real-device failure 优先于继续扩展 BotC。

最终原则：

> **网络层越复杂，游戏规则层越应该保持简单；客户端越多，authoritative source of truth 越应该集中。**
