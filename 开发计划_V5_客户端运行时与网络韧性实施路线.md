## 3. E2.1 的长期定位

E2.1 是成功的迁移切片，但不是最终客户端 API。

当前：

```text
public/app.js
   ↓ legacy game event name
webClientProtocol bridge
   ↓
client:command envelope
```

最终：

```text
UI
  ↓ semantic client action
ClientSession / game client adapter
  ↓
E1 protocol
```

因此：

> `player:submit-wolf-target`、`player:submit-vote`、`host:start-night` 等 legacy event name 不能成为长期 UI contract。

E2.1 bridge 明确标记为 migration shim；等 E2.2/E2.3 完成后逐步收缩。

# 6. E2.2 — Client Runtime / Connection FSM ← 当前阶段

## 6.1 目标

建立一个 transport-neutral client runtime，使浏览器和未来微信客户端共享以下语义：

```text
command lifecycle
connection lifecycle
authoritative PlayerView
revision reconciliation
reconnect synchronization
realtime effect dispatch
```

核心不变量：

> **Socket connected 不等于 game session synchronized。**

客户端只有在 authoritative PlayerView 已成功同步后，才进入 `Connected`。

---

# 7. E2.2a — Client Connection FSM + Authoritative State Store ← 下一 PR

这是当前建议的**最小下一 PR**。

## 7.1 新增 ClientConnectionFSM

建议状态：

```text
Idle
Connecting
Syncing
Connected
Disconnected
Reconnecting
Failed
Disposed
```

第一 PR 可以只实现真正需要的 transition，不必为了状态名预先加大量行为。

FSM 必须是 pure function：

```text
(context, event)
   ↓
nextContext + effects
```

不得 import：

- Socket.IO；
- Cloudflare runtime；
- DOM；
- `wx`；
- Werewolf rules。

## 7.2 新增 Authoritative Client State Store

负责保存：

```text
roomId
playerId
revision
playerView / protocol state envelope
session generation
```

基本 revision 规则：

```text
new revision > local -> apply
new revision == local -> duplicate / ignore
new revision < local -> stale / reject according to transport context
```

State Store 不自行计算 Werewolf state transition。

## 7.3 generation guard

解决：

```text
reconnect A starts fetch
reconnect B starts later
B succeeds
A late response arrives
```

A 必须被丢弃。

每次 bind / reconnect generation / leave / switch session 都有明确 generation。

## 7.4 E2.2a 测试

至少覆盖：

1. `Idle -> Connecting -> Syncing -> Connected`；
2. socket open 但没有 state 时不得进入 Connected；
3. Connected -> Disconnected -> Reconnecting -> Syncing -> Connected；
4. duplicate revision 不重复 apply；
5. stale revision 不覆盖新 view；
6. stale generation result 不应用；
7. protocol failure -> Failed；
8. dispose 后忽略后续 network event；
9. game layer 不 import client runtime；
10. client runtime 不 import Node / Cloudflare transport。

## 7.5 E2.2a 明确不做

- 不立即改生产 `public/app.js` reconnect；
- 不移除 Socket.IO；
- 不引入微信代码；
- 不做 Effect Outbox；
- 不改 Werewolf rule；
- 不改 C4 timeout/recovery；
- 不进行 Cloudflare cutover。

这保证第一 PR 仍是 architecture seam，而不是大迁移。

# 8. E2.2b — Web ClientSession + SocketIoRealtimeTransport

E2.2a 稳定后开始接生产 Web。

## 8.1 ClientSession

ClientSession 负责组合：

```text
Command Adapter
Connection FSM
State Store
Realtime Transport
Effect Dispatcher
```

UI 只通过 ClientSession 读取：

- current connection state；
- current authoritative view；
- semantic command API；
- transient local effects。

## 8.2 SocketIoRealtimeTransport

把现有 Socket.IO 约束在 transport adapter 中。

Transport 负责：

- connect；
- disconnect；
- send；
- parse wire event；
- open / close / error callback。

Transport 不负责：

- reconnect policy；
- revision；
- game state；
- vibration；
- UI。

## 8.3 Web reconnect 新合同

```text
transport reconnected
      ↓
Syncing
      ↓
authoritative player state fetched/received
      ↓
revision applied
      ↓
Connected
```

不能恢复成：

```text
socket.connect -> Connected
```

## 8.4 Browser lifecycle

统一处理：

- `visibilitychange`；
- online/offline；
- pageshow / focus（如实测需要）。

foreground 时：

```text
if transport unhealthy
   -> reconnect
else if session synchronization uncertain
   -> resync authoritative state
```

# 9. E2.2c — Realtime Effect Dispatcher

将当前短暂展示/提醒行为从 Socket event name 中抽离。

长期：

```text
protocol realtime event
       ↓
EffectDispatcher
   ├─ vibration
   ├─ audio
   ├─ animation
   └─ toast/highlight
```

规则：

- authoritative state 不能依赖 effect 是否成功播放；
- effect 可以重复或丢失而不改变游戏事实；
- reconnect 后以 PlayerView 恢复，不依赖 replay 所有 vibration/audio event。

---

# 10. E2.3 — Legacy Realtime Boundary Contraction

完成 E2.2 后逐步减少 legacy application Socket.IO surface。

目标：

```text
legacy server event
        ↓
compatibility adapter only
```

而生产 Web 主路径使用：

```text
Command
State
Realtime Event
Reconnect
```

四类 E1 contract。

E2.3 可以分多个小 PR：

1. state / private PlayerView；
2. reconnect/session；
3. realtime effect；
4. room lifecycle / management；
5. 删除确认无调用的 legacy handler。

原则：每删除一组 legacy event，必须有 integration regression test 证明现有游戏流程不变。


# 13. R1 — Reliability Hardening / Effect Outbox

这一阶段放在 Client Runtime 稳定后、正式生产 cutover 前。

目标解决：

```text
state commit success
but post-commit external effect delivery interrupted
```

参考 WerewolfGameJudge transactional outbox 思路。

候选：

```text
command receipt
+ authoritative state
+ durable effect record
```

形成同一 commit boundary。

然后通过 DO alarm / retry worker 执行 effect。

第一阶段不要把所有震动/动画 durable 化。

只处理真正需要 server-side eventual delivery 的 effect。

---

# 14. Durable User Event 的采用原则

仅当满足：

```text
must eventually reach one user
AND cannot be reconstructed from PlayerView
AND has stable eventId
AND supports ACK
```

才加入 durable user inbox。

普通 room recovery 不改变 E1 原则：

```text
reconnect -> authoritative state
```

而不是：

```text
reconnect -> replay full event history
```

# 22. 开发纪律

继续采用：

```text
small PR
→ contract
→ production integration
→ regression / parity tests
→ typecheck
→ full test
→ CI
→ merge
```

对于参考项目，只借已经理解且与本项目边界一致的设计；不因为参考实现功能更多就把未验证复杂度整体搬入。

最终原则：

> **网络层越复杂，游戏规则层越应该保持简单；客户端越多，authoritative source of truth 越应该集中。**
