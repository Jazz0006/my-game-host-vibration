# 3. 当前必须保持的核心不变量

## 3.1 Authoritative state

private authoritative PlayerView 只通过：

```text
client:state
```

进入：

```text
ClientSession
→ AuthoritativeClientStateStore
→ UI rendering
```

`room:state` 仍然是 production Web 的 public / Host room UI contract，当前必须保留。

## 3.2 Reconnect

Reconnect 的 source of truth 是 authoritative state：

```text
reconnect
  ↓
identity restored
  ↓
authoritative PlayerView sync
  ↓
revision reconciliation
```

不是：

```text
reconnect -> replay full realtime history
```

## 3.3 Connection state

Socket connected 不等于 game session synchronized。

标准路径：

```text
Connecting / Reconnecting
        ↓ transport open
Syncing
        ↓ authoritative PlayerView accepted
Connected
```

## 3.4 Revision / generation

- newer revision：apply；
- equal revision：duplicate，合法；
- lower revision：stale；
- stale generation：ignore；
- reconnect 可以推进 generation，但保留最后可信 PlayerView，直到新 generation 同步完成。

## 3.5 Transient realtime effects

```text
client:event
```

承载 transient effects / lifecycle events。

普通 vibration / audio：

- 可以丢失；
- 可以重复；
- 可以乱序；
- malformed transient effect 必须 nonfatal；
- unsupported browser capability 必须安全 no-op；
- reconnect 不要求 replay 全部 transient history。

Effect Outbox 仍属于 R1，不提前混入 E3。

# 4. 当前 stable Web runtime

当前 production Web 主路径已经是：

```text
browser UI intention
    ↓
webClientProtocol compatibility bridge
    ↓
ClientSession / SocketIoRealtimeTransport
    ↓
client:command envelope
    ↓
SocketIoClientProtocolTransport
    ↓
shared authoritative runtime
```

服务器返回明确分为：

```text
private authoritative PlayerView  → client:state
transient effect / lifecycle      → client:event
public / Host room UI             → room:state
```

E2.1 compatibility bridge 仍允许 `public/app.js` 暂时使用旧 UI event name，但这些旧名称已经不再是 Node wire-level Werewolf command handlers。

# 7. E2.3 验收结论

当前必须长期保持：

```text
raw production Werewolf game commands = 0
```

以及：

```text
Web UI legacy game event names
    ↓ compatibility bridge
client:command
    ↓ stable protocol type
canonical Node protocol transport
```

不能重新在 `src/server.ts` 添加类似：

```text
socket.on("player:submit-...")
socket.on("host:start-night")
socket.on("host:start-game")
```

如果未来出现新的狼人杀游戏动作，应先定义 stable semantic protocol command，而不是增加新的 raw Socket.IO gameplay event。

# 8. 开发节奏调整

项目目前是单人开发，且多数 boundary change 已经进入低风险收缩阶段，因此不再要求“一条 handler 一个 PR”。

后续默认采用：

```text
一个清晰的逻辑批次
    ↓
一个 branch
    ↓
逐项 implementation + compare audit
    ↓
一个 PR
    ↓
full CI
    ↓
squash merge
```

推荐粒度：

```text
3–5 个同构小改动 / PR
1–2 个复杂 lifecycle / recovery change / PR
重大架构边界单独 PR
```

仍然不建议直接在 main 上开发，因为 branch + PR 提供：

- CI isolation；
- connector whole-file write 风险隔离；
- 最终 diff audit；
- 干净 squash history。

# 9. E3 — Native WeChat Thin Client ← 当前下一阶段

## 9.1 目标

微信客户端不是复制 Web 应用，也不是复制狼人杀规则引擎。

目标架构：

```text
WeChat UI
   ↓
WeChat ClientSession adapter
   ↓
shared stable client protocol
   ↓
Cloudflare Raw WebSocket / production transport
   ↓
authoritative runtime
```

微信侧只实现 platform capabilities：

```text
wx.connectSocket
local storage resume credentials
app/page lifecycle
vibration
semantic audio
native UI rendering
```

狼人杀：

```text
rule
phase machine
authority
idempotency
PlayerView generation
```

仍然留在 authoritative server/domain runtime。

## 9.2 E3 第一阶段不要做什么

不要一开始就：

- 做完整微信 UI；
- 做商业级视觉设计；
- 切 production traffic；
- 删除 `room:state`；
- 重做 session/account system；
- 实现支付/登录；
- 扩展 BotC；
- 把 Web 与微信逻辑复制两份。

## 9.3 推荐的 E3 起步顺序

```text
E3.1 WeChat transport / runtime boundary audit
    ↓
E3.2 minimal WeChat ClientSession transport adapter
    ↓
E3.3 authoritative state sync + reconnect PoC
    ↓
E3.4 command ACK / retry PoC
    ↓
E3.5 vibration/audio capability adapter
    ↓
E3.6 minimal lobby + one night-action vertical slice
    ↓
E3.7 real-device foreground/background validation
```

第一目标不是“做出整个小程序”，而是证明：

> 同一 stable protocol + ClientSession model 可以让第二种真实客户端工作，而无需复制 game logic。

# 11. Cloudflare transport 的位置

Cloudflare D4 server transport 已存在，但当前 production Web 仍使用 Node Socket.IO。

长期 transport swap：

```text
ClientSession
   ├─ SocketIoRealtimeTransport   // current production Web
   └─ CloudflareRealtimeTransport // future Web / WeChat transport
```

认证方向：

```text
resumeToken
   ↓
HTTP websocket-ticket
   ↓
short-lived one-time ticket
   ↓
Raw WebSocket
```

ClientSession 不应感知：

```text
Socket.IO vs Raw WebSocket
```

Production cutover 前必须证明 transport swap 不改变：

- command semantics；
- private PlayerView；
- reconnect synchronization；
- effect delivery policy。

# 12. R1 — Reliability Hardening / Effect Outbox

E3 基本 vertical slice 与 transport boundary 稳定之后，再进入 R1。

目标解决：

```text
state commit success
but post-commit external effect delivery interrupted
```

候选：

```text
command receipt
+ authoritative state
+ durable effect record
```

形成同一 commit boundary，再由 DO alarm / retry worker 执行需要 eventual delivery 的 effect。

普通 vibration/audio 不默认 durable 化。

只有满足：

```text
must eventually reach one user
AND cannot be reconstructed from PlayerView
AND has stable eventId
AND supports ACK
```

才考虑 durable user inbox。

# 18. 开发纪律

继续采用：

```text
inspect design + current code
→ choose one logical batch
→ contract / regression tests
→ production integration
→ typecheck
→ full test
→ CI
→ final diff audit
→ squash merge
```

原则：

- 不因为某 legacy event “看起来旧”就删除；
- production Web 不应同时消费新旧两条等价 effect/state path；
- public room state 与 private PlayerView 分开判断；
- recovery correctness 优先于 transport cleanup 的整齐程度；
- platform adapter 不复制 authoritative game logic；
- 一个逻辑批次可以包含多个同构小改动，减少 branch / PR / CI 开销；
- 重大架构变化仍单独 PR；
- GitHub connector 的 whole-file write 必须用 compare + CI 审计。

最终原则：

> **网络层越复杂，游戏规则层越应该保持简单；客户端越多，authoritative source of truth 越应该集中。**
