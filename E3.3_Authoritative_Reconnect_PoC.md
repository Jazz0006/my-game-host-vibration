# E3.3 Authoritative State Sync + Reconnect PoC

## Scope

E3.3 proves that the native WeChat client can recover from a lost realtime connection without replaying transient history or duplicating game logic.

## Proven paths

### Physical disconnect / reconnect

```text
Connected generation N
  -> transport closes
Disconnected (last trusted PlayerView retained)
  -> reconnect()
Reconnecting generation N+1
  -> new short-lived WebSocket ticket
  -> new physical socket opens
Syncing (old PlayerView still retained)
  -> current authoritative state accepted
Connected generation N+1
```

Late frames from the old physical socket/generation are ignored.

### Healthy foreground resync

```text
Connected generation N
  -> resync()
Syncing generation N
  -> current authoritative state accepted on existing socket
Connected generation N
```

A healthy foreground revalidation does not open a new socket or advance generation.

## Boundaries

- authoritative state remains the reconnect source of truth;
- missed `client:event` history is not replayed;
- UI does not derive or reconstruct game state locally;
- reconnect identity remains `roomId + playerId + resumeToken` exchanged for a short-lived WebSocket ticket;
- command ACK/retry remains E3.4;
- lifecycle signal wiring remains E3.1;
- vibration/audio capability mapping remains E3.5.
